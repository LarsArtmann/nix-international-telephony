The headline

Two headless chromium browsers now register through wss://pbx.test/sip and complete a real 1000→1001 WebRTC call (DTLS-SRTP), asserted server-side via fs_cli while the call is up. Getting there required fixing four stacked bugs that made the webphone completely non-functional in production: an nginx prefix-location trap, a Via-transport mismatch that silently ate every browser REGISTER, an ICE-candidate ACL that rejected all LAN clients, and an over-escaped dial-string template that killed extension bridging. All four are fixed, regression-guarded where cheap, and documented in AGENTS.md.

AFully Done

Evidence: CI runs 32551406890 / 32552409932 failed; run 32570862334 green after fix. Same bug class found and fixed twice (also useFsSecrets → fsSecrets), both now hoisted into the let.

Repeated

Fixed fsSecrets referencing gatewaysForFs (sibling scope), then my own reordering re-created the same class with useFsSecrets → fsSecrets. Only caught because I eval'd locally before pushing. Lesson recorded in AGENTS.md: cross-referencing values in shared.nix belong in the let.

Wasted rounds

Concrete own-goals: wsprobe.py unstaged (the git-tree flake-source trap documented in AGENTS.md — one round); a SyntaxError only inside the VM from f-string backslash escapes because I started syntax-checking after that round, not before every round; a literal ${} inside an XML comment broke eval (known rule, written anyway); an imprecise multiedit clobbered comment lines; a FEATURES.md edit replaced a row instead of inserting. Each cost a ~5-minute VM cycle.

Blind first

Three sequential blind spots, each one round to discover: Selenium .text returns "" for hidden subtrees (the webphone log list sits in the hidden-until-login phone view) — read textContent; CSS text-transform: uppercase silently broke a case-sensitive substring wait; and post-mortem registration dumps are useless for WS clients because registrations die with the connection. All three now encoded in AGENTS.md.
