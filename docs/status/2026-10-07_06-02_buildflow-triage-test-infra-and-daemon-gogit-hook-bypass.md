## e) WHAT WE SHOULD IMPROVE

1. **"Source-verified" must name the exact function that performs the operation.** `--no-verify` absence in pma's source proved nothing because the operation lives in a dependency (`go-commit` → go-git). Rule: a bypass-safety claim is only as deep as the deepest repo in the call chain that actually executes the thing.
2. **Never measure exit status after a pipe.** `cmd | tail; $?` measures `tail`. For verdicts: no pipe, or `PIPESTATUS[0]`, or write output to a file and echo `$?` immediately. The canary protocol in scripts should encode this (a future verify-hook-selfheal.sh must assert on git's status, not on captured text alone).
3. **Verify the STEP, not an approximation of the step.** I proved `pytest` works in `nix develop -c pytest`, but buildflow's pytest-test step selects its OWN env (`[env: nix-run]` vs `[env: nix-develop]`); the fix claim (pin → env flip → project deps) is only proven by `buildflow -s pytest-test` post-pin. Same class as the prior session's `nix develop -c true` no-op verification (05-25 §d4): prove the fire condition of the actual consumer.
4. **A DECIDED-clean state decays silently; re-run the gate, don't cite the decision.** vulture-clean and mypy-clean were both documented as states, while both had quietly rotted (three findings; zero files checked). Any "X is clean (decided YYYY-MM-DD)" line in AGENTS.md should be read as "X was clean when last measured" — and anything that unblocks a checker (like fixing a module-mapping error) must be followed by a FULL re-run of that checker, because unblocking surfaces everything it never reached.
5. **Lock forensics reflex order: compare revs first, narrate never.** `git show HEAD:<file>` vs worktree vs `git log -S <rev> -- <file>` answers "did it move, when, and by which commit" in three commands. The sweep's `git log -S` fingerprint (`5c811e5` the sole introducer of `77f2a16`) did more than an hour of mechanism hypothesizing.
6. **Follow the commit path, not the commit story.** The daemon's true behavior was three greps away (pma committer.go → go-commit → NewGoGitWithRetry). When a gate "mysteriously" doesn't fire, the question is never "why didn't the hook see it" but "does anything in this lane execute hooks at all".
7. **Session-start lane checks should attribute processes to repos** (`readlink /proc/<pid>/cwd`) — I correctly avoided disturbing the sibling's nix lanes but could not say WHAT they were building, which limited how much signal I could take from eval-cache contention during my own runs.
