## e) WHAT WE SHOULD IMPROVE (design debt)

1. **Secrets in store** — biggest one. Extension passwords, gateway
   credentials, TURN secret, event-socket password all bake into
   world-readable `/nix/store` XML/JS. Needs a story (sops-nix template
   render at activation, or FS DB directory) before any real exposure.
2. **TURN credentials in served config.js** — anyone who can load the page
   can relay through the host. Consider per-session REST-auth TURN
   (`use-auth-secret` + generated short-lived creds) instead of static user.
3. **Single gateway** — module type forces `nullOr (submodule …)`; multiple
   trunks + least-cost routing is a natural next data-model step (list-of
   instead of single).
4. **Emergency calling** — README disclaimer only; no KPI/calling-plan
   infrastructure. Keep it loud, not silent.
5. ~~**Webphone license** — esbuild `--minify` strips SIP.js MIT header; ship~~ done at `0aa7e92`
   LICENSE alongside the bundle (README mentions MIT but repo has no LICENSE
   file at all — inconsistent).
6. **Test depth** — dialplan proven via loopback originate, but no SIP UAS
   register test (e.g. register a softphone via `sofia profile external`
   register or a scripted REGISTER over TCP) and no media/DTMF check.
7. **module option ergonomics** — `sounds.package` null-vs-set is subtle;
   could add `sounds.enable` sugar. `tls.mode` could grow an `acme` mode
   that wires `security.acme` itself.
8. **Static asset quality** — app.js is one IIFE with no CSP hash story;
   nginx default headers fine, but a `Content-Security-Policy` would be
   cheap wins; assets not minified/linted beyond prettier.
