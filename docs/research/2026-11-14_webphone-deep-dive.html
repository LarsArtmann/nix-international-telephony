02Capability assessment

Ordered by impact. Carried rows keep their 2026-10-25 numbers where the grade is unchanged.

Partially Used · Medium impact, deliberate decision needed

The oauth2 facade now has an upstream twin

modules/telephony/options.nix:1979+ (consumer facade) · upstream package/oauth2.nix (NEW since 2.10.0)

The consumer facade (issuer, clientSecretFile as runtime file, users map, fail-closed assertions, passwordFiles lifeline) was built in October when upstream offered only freeform settings. Since 2.10.0 upstream ships a typed services.webphone.oauth2.* with its own fail-closed assertions, systemd-credential secret loading, passkey RP derivation from the vhost, and a scope guard. Both render the same settings.auth.oauth2.* tree; the consumer facade additionally integrates the email→extension users map and per-extension password files this stack's login contract needs. Two parallel typed surfaces for one config tree is a split-brain liability: option drift between them will eventually bite a consumer mixing both vocabularies.

Recommendation Diff the two surfaces option by option; if upstream's seam can carry the users-map/passwordFiles integration, retire the consumer facade onto it (one eval-arm rewrite). If not, document the deliberate fork in the facade's option descriptions so the twin is a known decision, not an accident.
Missed Opportunity · Medium-high impact (owner-gated since first audit)

ASR transcription still unwired; the summary-draft family waits on it

nowhere in modules/ · upstream settings.asr.* + /api/transcribe + /api/calls/{id}/summary-draft

The gap is unchanged since 2026-10-01 but its blast radius grew: the call-card summarize affordance (config.js agent key, value-pinned false), the post-call summary-draft API, and voicemail transcription all sit behind the same owner decision. What IS new: asr.provider = "whispercpp" makes LOCAL transcription possible (no cloud provider, no per-minute cost, no audio egress), and asrLocality gives the config-honest trust label ("local"/"remote") the UI already knows how to display. The open question is no longer "which cloud" but "local or none".

Recommendation If caller-audio privacy is the blocker, whispercpp answers it: a facade option pair (asr.provider, model path, optional GPU flag) with eval arms, mirroring the textagent facade pattern. Note the configjs fixture then moves from type-checking asr to value-pinning it, and agent flips only if the textagent seam is also wired.
Missed Opportunity · Medium impact (tracked TODO)

Push transports: ring landed, nty/FCM did not

modules/telephony/ has no push option surface · upstream push.ntfy/push.fcm + /api/push-devices + wire fixtures

Half the 2026-10-25 finding 1 landed: the ring producer (ringhook) feeds /hooks/ring. The other half, the notification transports (push.ntfy.{url,token}, push.fcm.credentials_file) and with them the device-registry value, remain unwired (TODO row: "Push transports, wire push.ntfy / push.fcm through this stack", est. 1h). Upstream shipped FCM+ntfy wire fixtures for the ring/ring_end/draft_ready events in 2.13.0, so the payload shapes to assert against are now checked in upstream.

Recommendation The TODO row's shape is right: NixOS option surface + env-file wiring + eval assertions + a configjs arm, mirroring the ASR facade pattern. Pin the shim/suite assertions against docs/contracts/wire/ while at it (finding 8).
Missed Opportunity · Medium impact, new since 2.10.0

CRM seam unwired while a real CRM sits in the fleet

no crm facade · upstream services.webphone.crm.* (url, tokenFile, caFile) + /partials/live-context

Upstream's typed CRM lane (contact enrichment, click-to-call logging, live-call context) has a genuinely applicable consumer here: the deployment fleet runs Kith CRM at crm.home.lan (SystemNix services.crm-server on evo-x2, reached over the NetBird mesh), and the live PBX host already monitors that reachability (pbx-artmann crm-reachability.nix, 2026-10-23). Nothing on the webphone side consumes it: no facade options, no token wiring. This is the same "seam exists, deployment picture has the counterpart" shape that flipped paperless from N/A-gated to relevant once an instance existed.

Recommendation Owner decision first (does Kith expose the API surface webphone's crm lane expects?); if yes, the facade is small: crm.url + crm.tokenFile + optional caFile with exactly-one-of discipline, following the paperless facade sketch already written down in FEATURES.md.
Missed Opportunity · Low impact, trivial effort

Flight recorder option: the browser-postmortem tool this repo's own lessons file wishes for

not set anywhere · upstream services.webphone.debug.flightrecorder.enable (NEW) + GET /internal/flightrecorder

The module option landed since the audit: one boolean turns on a ring-buffered diagnostic snapshot exposed at loopback-only /internal/flightrecorder (rate-limited, disk-floored, counted in /metrics). docs/lessons/webrtc-browser.md records the four-reason browser postmortem that this exact tool shortens: the next silent-WebRTC regression would be diagnosable from the snapshot instead of a session like the 2026-09 four-reason fight.

Recommendation Enable it on the demo host (free) and add the option to the prod template's commented diagnostic block; document the fetch command (loopback + journal tail) in the ops runbook.
Missed Opportunity · Low impact

Island latency beacon and the /metrics scraping void

Missed Opportunity · Low impact, hardening

Ringhook payload not pinned against upstream's wire fixtures

tests/test_ringhook.py (hand-written payload asserts) · upstream docs/contracts/wire/ (NEW 2.13.0)

Upstream checked in the exact wire shapes for ring/ring_end/draft_ready (FCM and nty arms) plus session-identity fixtures. The shim's tests assert a hand-written payload; if upstream ever broadens the accepted envelope, the consumer learns it from a red suite instead of a diff. A contract-lock test that reads the fixture files (vendored or fetched at test time) makes the cross-repo seam self-verifying.

Recommendation Copy the two ring fixtures into tests/fixtures/ with a provenance-comment (rev they were taken from) and assert the shim's forward payload matches field-for-field; refresh them on each relock ritual as part of gate 5's seam scan.
