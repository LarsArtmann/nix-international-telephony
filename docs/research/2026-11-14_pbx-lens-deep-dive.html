00Summary

The deploy surface this repo built around pbx-lens (modules/telephony/lens.nix, 511 lines) is genuinely superb: the native passkey + OIDC identity lanes, verified-snapshot backups with the non-disposable identity DB staged conditionally, the retention purge timers, sd_notify + watchdog, and a sandbox set that exceeds upstream's own draft unit are all first-class, eval-asserted and VM-proven. The score is held back by a tight cluster of operational gaps, not by wiring quality: the module's source-access render stops at the CDR file (the live host hand-wires the webhook, transcripts and recordings access), nothing anywhere consumes the freshness/metrics surfaces the binary serves for alerting, and the operator verbs (refresh, purge -dry-run, smoke) have no module or runbook story.

The bottom line Yes, superbly on the deploy surface; the remaining value is operational: grow the CDR-style access render to the other three sources, and give the lens a health/alert arm so /api/ops freshness and the metrics endpoint stop being write-only surfaces.

01Current usage (the baseline)

The consumer relationship is deliberately split: pbx-lens ships ONLY the binary (packages.default, honestly licenses.unfree, re-instantiated with allowUnfree upstream so this flake's eval stays clean); this repo's nixosModules.telephony wrapper defaults the package and modules/telephony/lens.nix owns everything deploy-shaped (upstream's deploy/nixos/module-draft.nix is marked SUPERSEDED, pointing here). Adoption spans three tiers:

+
Full option surface, 34 options across 3 CLI verbs serve (18 flags wired incl. all five OIDC flags), backup, purge — modules/telephony/lens.nix:331-372, 417-435, 473-478.
+
Identity lanes, fail-closed by construction Passkey (auth.enable + publicOrigin) and Pocket ID OIDC (five options, three eval assertions incl. the non-empty groups allowlist — the security boundary; the 2026-11-13 groups-scope fix relock aa9e51b proved the loop) — lens.nix:262-294, tests/eval.nix:1119-1300.
+
CDR access via the operator's three-layer path ro-bind + telephony-fs supplementary group + ACL unit ordering, exactly like the operator API — lens.nix:301-330, VM-proven end to end (checks.telephony-lens).
+
Backup staging with the right disposability doctrine Nightly verified snapshot (timer, Persistent); identity.db staged beside the index only when auth is on; the preStart mkdir for the staging dir was a real bug this suite drove out — lens.nix:403-460, tests/lens.nix:151-157.
+
systemd integration beyond the upstream draft Type=notify + WatchdogSec=30 (the binary feeds sd_notify at half), DynamicUser, systemd credentials for both secrets, full sandbox set — lens.nix:311-400.
+
State registration and retention backups/ + index.db + conditional identity.db registered in services.telephony.state (default.nix:86-105, eval-asserted); demo host runs a 90-day purge window end to end.

Live adoption is real, not theoretical The production deployment repo (pbx-artmann) enables the lens with ALL sources, the real Telnyx key, both-spelling aiDids, passkey+OIDC auth behind lens.artmann.tech (pure proxy; the lens owns login end to end).

02Capability assessment

Ordered by impact. Every grade cites the consumer code and the upstream surface.

Partially Used · High impact

The source-access render stops at the CDR file

modules/telephony/lens.nix:301-330 · webhookLog, transcriptsDir, recordingsDir have no access story

Upstream reads four sources; the module renders the three-layer access path (ro-bind + group + ACL ordering) only for cdrFile. The live host documents the gap itself: the messaging ro-bind for the webhook JSONL and the telephony group for transcripts/recordings are wired host-side in pbx-artmann/hosts/pbx/default.nix:1312-1331, with the note "strike each entry upstream-side when the sibling grows it". Until then every new consumer of webhookLog/transcriptsDir/ recordingsDir rediscovers the cold-start trap the live comment records (systemd binds an EMPTY dir if the bridge state does not exist at lens start, proven in this repo's VM suite 2026-10-13).

Recommendation Grow the render the module already owns: when webhookLog is set, bind the bridge dir read-only the way pbx.nix does for the operator and order after the ACL unit; when transcriptsDir/recordingsDir are set, take the recordings group as SupplementaryGroups (or an option) instead of leaving it host-side. Three eval arms + one VM row per source, mirroring the CDR lane. 
# modules/telephony/lens.nix — the CDR render, worth copying per source
BindReadOnlyPaths = lib.optionals (cfg.cdrFile != null) [
  "/var/lib/private/freeswitch:/var/lib/telephony/freeswitch-ro"
];
SupplementaryGroups =
  lib.optionals (cfg.cdrFile != null) [ "telephony-fs" ];
Missed Opportunity · Medium impact, trivial effort

The alerting recipe is unconsumed: freshness, staleness and metrics have no consumer

modules/telephony/monitoring.nix (no lens arm) · upstream README "Alerting recipe" + /api/ops + /metrics

Upstream serves exactly the operational surfaces an operator should alert on: /api/ops carries last_pass_age_seconds (-1 = poller never ran), per-source coverage vs the 48h SLO, and retention purge_lag_seconds; /health/ready ANDs projection health into readiness; /metrics (deliberately unauthenticated, perimeter = bind address) carries build info and index-shape counters. This repo consumes none of it: monitoring.nix probes webphone /healthz only, the module's monitoring.scrape.enable scrape target is enabled by no host anywhere (demo, prod template, live host all off), and no runbook recipe maps the README's alert fields onto the stack's alerts.* OnFailure webhook. The live host probes only /login liveness.

Recommendation Two small arms close this: a telephony-lens-freshness check unit (curl /api/ops, fail when last_pass_age_seconds exceeds 2-3 poll intervals or is -1) wired into the existing alerts lane, and enabling monitoring.scrape.enable on the live host so the Prometheus counters finally land somewhere.
Missed Opportunity · Medium impact, low effort

No story for the refresh backfill verb (the ContentHash-v2 re-ingest)

cmd/pbx-lens/refresh.go (upstream) · no module option, no runbook recipe

Upstream's refresh verb exists precisely for the operational moment this deployment will eventually hit: a schema or content-hash bump (v2 landed 2026-10-23) that requires a one-time re-ingest / read-model rebuild. Upstream's TODO marks the prod re-ingest owner-gated. The consumer has neither a module option nor a runbook section for it, so the operator's first encounter with "refresh classify vs apply" will be mid-incident.

Recommendation Add a "Backfill and schema bumps" recipe to the runbook's pbx-lens section: run refresh classify-only from the store binary against the index, review the verdict counts, then -apply; note that FTS rebuilds and enrichment is skipped (it owns its own hash). A lens.refresh.* oneshot service can come later if the recipe sees reuse.
Missed Opportunity · Low impact, trivial effort

purge -dry-run / -json and the smoke canary are unwired

modules/telephony/lens.nix:473-478 · upstream ops.go:30-35, 135-160

The purge timer always runs in apply mode; upstream's -dry-run + -json give a free pre-flight report (what WOULD retire) that would make enabling retention.maxAge on the live host a data-backed decision instead of an act of faith. The smoke verb (in-memory index + optional backdated row) is a natural canary for the VM suite and for post-deploy probes.

Recommendation Give the purge timer a retention.dryRun passthrough (a one-line ExecStart conditional), and use one pbx-lens smoke invocation in tests/lens.nix as the cheapest possible boot proof of the binary itself.
Partially Used · Low impact

CSP hardening knobs not surfaced (nonce mode, report-only dry run)

modules/telephony/lens.nix (no Environment) · upstream serve.go:404-423 (CSP_NONCE, CSP_REPORT_ONLY)

The binary can serve a nonce-based CSP and can dry-run a stricter policy via Content-Security-Policy-Report-Only. With the lens now actually exposed at lens.artmann.tech these are no longer theoretical; the module passes neither env var. Upstream's own CSP enforce-mode flip is an owner decision there, but the consumer-side switch should be one option, not an env override to rediscover.

Recommendation A csp.nonce / csp.reportOnly bool pair rendering Environment = lines keeps the hardening story in the typed surface where the rest of the lens already lives.
Doc drift · Fixed on sight during this audit

Stale htpasswd mentions in FEATURES.md and the demo host comment

FEATURES.md pbx-lens row · hosts/pbx/default.nix:112-115

Upstream removed htpasswd entirely on 2026-11-11 (native identity replaced it); the module correctly moved to auth.enable/OIDC, but the FEATURES row still cites "Telnyx-key/htpasswd systemd credentials" and the demo host comment still says "set htpasswdFile before exposing it through a proxy" — an option that no longer exists. An operator following that comment into the module finds nothing. (Corrected in the same commit as this report.)

05Conclusion

78/100, high band: the deployment-facing half of pbx-lens is used superbly (identity, backup, retention, sandboxing, state registration, live exposure all first-class and proven), and the pin tracks upstream HEAD exactly. The 22% left on the table is operational plumbing: finish the source-access render so the live host's hand-wires can be struck, and give the served freshness/metrics surfaces their first consumer. The single highest-leverage step is finding 2 (the freshness/alert arm): it is a few dozen lines against surfaces the binary already serves, and it converts the index from a UI into an observable component.
