00Summary

The telephony flake consumes nix-ssh-config exactly the way the library intends: module wired in both example hosts, operator keys from the sshKeys export, the whole hardening suite (post-quantum KEX first, AEAD ciphers, ETM MACs, LoginGraceTime 30, PerSourcePenalties) received implicitly, and a VM suite that behaviourally proves the effective config — including the mlkem768x25519 negotiation. Two defects surfaced: the production template shipped PermitRootLogin no while its own runbook mandates nixos-rebuild --target-host root@<host> (no other login user exists → every documented update path was refused post-install), and both hosts hand-set KbdInteractiveAuthentication through extraSettings even though the module default has covered it since v0.1.2.

The bottom line Adoption was already deep; the gap was not in missing features but in one unexamined default that broke the prod ops path. Both findings are fixed on this tree and verified by eval plus the telephony-ssh VM suite (green). The one remaining improvement lives upstream: the module’s binary allowRootLogin (yes/no) lacks the prohibit-password posture this consumer actually wants.

◆Current usage

The library enters as a flake input pinned to v0.1.3 with nixpkgs.follows (single nixpkgs in the closure). Its module is imported directly in flake.nix — where inputs are in scope — for both nixosConfigurations.pbx (demo VM) and nixosConfigurations.pbx-prod (production template); hosts/*.nix deliberately stay input-free. The ssh test suite receives the module as a function argument for the same reason.

01Findings

Ordered by impact. The first two were found by this audit and are already fixed and re-verified on this tree; the report keeps them because the reasoning matters for future host templates.

Misuse · High impact · FIXED

Prod template refused its own documented update path

flake.nix pbx-prod ssh-server block · docs/deploy.md:111,147 · hosts/pbx-prod defines no login user

The module’s allowRootLogin defaults to false (PermitRootLogin no) — correct as a library default. But the production template defines no other user, and docs/deploy.md’s whole update flow is nixos-rebuild switch --flake .#pbx-prod --target-host root@<host>. First install works (nixos-anywhere’s own installer-phase sshd), then every subsequent documented operation is refused: keys are authorized globally, but no account is permitted to use them. A green install with a bricked ops path. 

# Before (flake.nix, pbx-prod): default PermitRootLogin no
services.ssh-server = {
  enable = true;
  authorizedKeys = builtins.attrValues inputs.nix-ssh-config.sshKeys;
};  # root refused; no other user exists; runbook broken

# After: keys-only root == prohibit-password posture
services.ssh-server = {
  enable = true;
  authorizedKeys = builtins.attrValues inputs.nix-ssh-config.sshKeys;
  allowRootLogin = true;      # both password paths stay off (module default)
  allowUsers = [ "root" ];    # defense-in-depth: no other account may ssh
};
Fix applied & verified With passwordAuthentication and keyboard-interactive both off (module defaults, asserted in tests/ssh.nix), PermitRootLogin yes is functionally the prohibit-password posture. nix eval now shows PermitRootLogin "yes", AllowUsers ["root"], KbdInteractiveAuthentication false on pbx-prod, and the telephony-ssh VM suite is green.
Partially Used · Redundancy · FIXED

Hand-set KbdInteractiveAuthentication duplicated the module default through the wrong option

flake.nix pbx + pbx-prod (removed) · module option: modules/nixos/ssh.nix kbdInteractiveAuthentication

Both hosts set extraSettings.KbdInteractiveAuthentication = false with a five-line comment explaining the PAM door. Since upstream v0.1.2 the module’s kbdInteractiveAuthentication defaults to passwordAuthentication (false) — the exact lesson the comment encoded. The setting was not only redundant; it went through the freeform extraSettings escape hatch instead of the native, documented option, so it also shadowed the option’s own description and PAM-unixAuth coupling.

Fix applied & verified Both extraSettings lines deleted; the PAM-door knowledge lives in the library (option description) and AGENTS.md; the regression guard already exists as the kbdinteractiveauthentication no assertion in tests/ssh.nix. Effective config unchanged (verified by eval and the green VM suite).
Upstream opportunity · Open

Module lacks a prohibit-password root posture — the exact middle ground this consumer needs

modules/nixos/ssh.nix allowRootLogin (bool) · consumer: flake.nix pbx-prod comment now papers over it

OpenSSH’s canonical appliance posture is PermitRootLogin prohibit-password: root may use keys, never passwords. The module’s boolean collapses this into yes/no, forcing consumers that need keys-only root (any single-operator host managed via --target-host root@) to pick “yes” and explain in a comment why it is safe today — an explanation that silently becomes false the moment someone enables passwordAuthentication. A tri-state (or a separate rootLoginMode enum) would make the safe posture expressible and remove the comment dependency. 

# Upstream sketch: make prohibit-password a first-class value
allowRootLogin = lib.mkOption {
  type = lib.types.enum [ true false "prohibit-password" ];
  # "prohibit-password" emits PermitRootLogin prohibit-password;
  # independent of passwordAuthentication.
};
Not Applicable · Judged deliberately

2FA options, home-manager module, listenAddresses: unused on purpose

usePam, authenticationMethods, homeManagerModules.ssh, listenAddresses

usePam/authenticationMethods exist for PAM-backed two-factor auth — no 2FA requirement for a single-operator PBX (and the Unreleased PAM prompt fix only matters on that path). homeManagerModules.ssh targets client-side user configs; this flake is server-only. listenAddresses binds specific interfaces; the hosts are single-NIC cloud/VM machines where binding all interfaces at the module-managed port is correct. Not adopting these is the right call, not a gap.
